# 啤酒批发管家 V1.4

微信原生小程序，TypeScript 严格类型。本地业务数据保存在微信 storage，运行无需服务器、云环境或 npm 构建。

## 运行

1. 微信开发者工具选择「导入」，目录选择本 README 所在的 `beer-manager` 文件夹（不要选 `miniprogram` 子文件夹）。
2. 使用自己的小程序 AppID，或点击开发者工具的「测试号」。选择「不使用云服务」。
3. 点击「编译」。项目已配置 `useCompilerPlugins: ["typescript"]`，由工具直接编译 TS。
4. 若导入界面的旧占位 AppID 报系统错误，点击「测试号」或填写有效 AppID 后继续。
5. 基础库建议 3.7.6 或更高。无需「构建 npm」。手机预览需要有效 AppID 和开发者权限；历史版本曾在模拟器验收，V1.4 本轮验证范围见下文。

本机已经导入并运行工程；模拟器里的数据取决于本机测试状态，压缩包不包含设备里的业务数据。新设备首次运行按 seed 初始化；本机想从头验证时，可在「我的 → 数据重置」确认恢复初始数据。重置不可撤销，也会清除收据关联并尝试删除对应本地图片。

## V1.4 最终界面优化

统一为暖浅灰背景、白色卡片、深红主操作；绿色表示实收或结清，橙色表示提醒。标题、核心数字和辅助说明分层，保留全部已有业务能力。

- 首页取消版本标签，经营数字优先；仓库数量和低库存提醒集中在右侧，酒吧名称与提醒支持长文本换行。
- 酒吧卡片分开显示整箱、散瓶、待回瓶数；应收独立一行。业务流水按「类型与时间 → 酒吧与金额 → 明细」排列，金额更易扫读。
- 数量控件独占一行并始终标注箱/瓶；减加和 +1/+5/+10 均扩大点击区域。本次价格与包装分为等宽两栏，已选商品有边框提示。
- 客户详情固定操作区改为两列四个大按钮；收款方式和盘点位置同样使用等宽布局。长姓名、金额、管理操作和分析明细允许换行。
- 确认窗口保持固定标题、滚动明细和独立按钮区，使用明确的内容高度及上限；操作错误直接显示在底部确认按钮上方。
- 五个底部入口使用统一细线本地图标，中央「记一笔」保留红色突出入口。导航资源位于 `miniprogram/assets/icons/`，运行无需网络。

本轮修改集中在主题、组件和页面呈现；service、数据模型、storage key 与现有业务数据保留。2026-10-10 已完成严格 TS、22 个 WXML、25 个 WXSS 原生编译、JSON 检查，以及 56 项业务场景与两组页面事件复核。本次界面需要继续在微信开发者工具及爸爸的手机上查看；编译通过不等同于真机视觉验收。

## V1.3 新增：分类回瓶、剩余库存、周/月图表

- 确认弹窗采用统一布局：标题、逐项内容、独立操作区；长内容可滚动，取消不生成业务。
- 回瓶按商品区分 U8、纯生、白啤、鲜啤等种类，数量以瓶计。每种有独立余额，不能借用其他种类的待回数。整箱快捷键只负责换算瓶数。
- 分类回瓶默认开启「根据回瓶估算剩余库存」：每回 1 瓶扣该商品 1 瓶，显示整箱＋散瓶。例如 U8 14 箱（24 瓶/箱）回 13 瓶后为 13 箱＋11 瓶，待回数同步减少，仓库和欠款不变。若之前已经盘点扣除了售出的酒，应关闭该开关，避免重复扣减。
- 酒吧盘点支持整箱和散瓶。已有库存展示规格固定保存；新增送货按实际瓶数换算，不会因修改商品默认包装而凭空改变库存。
- 旧版空瓶余额保留为「历史未分类空瓶」。酒吧详情可将核实的数量归入某种商品，总待回不变并保存分类流水。未分类回瓶不能估算具体商品库存。
- 周统计以周一至周日为一周；月统计按自然月，可查看上一周/上个月。展示送货金额、实际收款、送货箱数、回瓶瓶数、商品与酒吧排行、每日明细。
- 原生轻量柱状图：周按天，月按 7 日区间展示；金额图同轴比较送货与实收，送货和回瓶使用独立单位。全部统计的图表展示最近 12 个月，汇总数字为累计。

**库存估算前提**：空瓶来自该酒吧已消耗的酒。未及时回瓶、空瓶丢失或混入其他来源会影响估算，不能替代实地盘点。历史库存默认按升级时的商品规格解释，旧版未保存的信息无法自动还原。初始空瓶余额也需人工核对分类。

## V1.2 新增：协商货款、经营分析、收据

- 送货中「协商后货款」可直接改总金额，留空采用计算金额。改变金额必须写说明；订单保存计算金额与最终金额，赊账、已付款、流水和分析均使用最终金额。
- 收款中输入实收和本次减免。应收 ¥3,420，实收 ¥3,400，减免 ¥20 可结清；减免留 0 时仍欠 ¥20。减免必须写说明，实收加减免不能超过当前应收。今日收款只计实际收到的钱。
- 「我的 → 经营分析」：自然周、自然月、全部；送货金额和箱数、实际收款、回瓶数、协商差额、收款减免、酒吧/商品送货排行、每日金额；当前应收和待回瓶始终展示实时余额，不随时间筛选改变。
- 点击任意业务流水进入详情，添加拍照/相册收据图片，每笔最多 6 张、单张不超过 5MB。图片使用文件系统持久保存并关联流水，支持放大预览和确认移除；保存失败不留下部分附件。V1 只保存在本机，无服务器上传、云端保存或多设备同步。PDF/Excel 文件暂不支持。
- 原有 V1.1 数据可直接读取，新增字段可选，未调整的旧单据按原总金额统计；无需重置。

## 功能

- 首页动态指标：今日送货、今日收款、当前应收、待回空瓶；仓库低库存、客户欠款、空瓶积压、客户低库存提醒。
- 酒吧名称搜索、最近操作排序、酒吧资料与库存详情、最近记录及全部客户记录、拨号入口（填写电话后）。
- 送货：多商品、减加与 +1/+5/+10、客户专属价自动带入、本次单价和瓶数可改、自动报价、赊账或已付款、五项数据一次保存。
- 按瓶回收散瓶，整箱可按可调包装一键换算；四种方式收款；回瓶超额和收款超额拦截。
- 进货、仓库盘点、酒吧盘点；库存变动包含修改前后与差额。
- 全部 / 送货 / 回瓶 / 收款 / 库存流水筛选。
- 商品新增、编辑及每箱瓶数调整；酒吧新增、编辑、删除和各商品专属售价；商品库存修改生成调整记录；重置与关于页面。
- 操作确认、错误提示、防重复提交、成功 Toast、客户业务完成后回到详情。

## 数据与口径

Mock 在 `miniprogram/mock/seed.ts`，storage key 为 `beer-manager:v1`。一个版本化 Database 快照包含商品、客户、客户库存、送货、收款、回瓶、库存变动和业务记录。各次写操作先修改读取的独立副本，通过校验后仅写入一次，避免验证失败后留下半条业务。

- 初始总应收 ¥5,280、待回空瓶 1,536 瓶；今日送货 / 今日收款为 0。没有虚构初始业务流水。
- 送货按每个商品本次箱数 × 每箱瓶数产生待回空瓶；默认 24 瓶/箱，可在商品管理修改默认规格或送货时改本次规格。规则集中在 `bottleService.accrueForDelivery`。
- 今日收款 = 当日独立收款 + 当日已付款送货。已付款送货不生成第二条收款流水，避免重复计算。
- 金额运算按分计算，业务模型以元保存；最多两位小数。仓库库存为整数箱；酒吧库存保存整箱和散瓶，空瓶数量为整数瓶。
- 日期按设备本地日期统计；小程序关闭后再次进入继续读取 storage。
- 酒吧库存是估算数量：送货增加对应实际瓶数，分类回瓶可按瓶扣减；实际销售消耗通过回瓶推算或盘点修正。盘点不改变应收和空瓶。
- 仓库提醒使用商品配置的阈值（严格低于）；客户总库存低于 10 箱、待回空瓶不少于 720 瓶产生首页提醒。这两项为 V1 默认规则。
- 联系人、电话、地址未给出的客户保持空值，页面显示「待补充」。

### V1.1 升级规则

快照版本升级为 2，storage key 保持不变。旧版待回瓶数、回瓶流水及历史送货包装按 **24 瓶/箱**自动换算；旧版没有包装信息，因此采用此默认假设。迁移前原始快照备份在 `beer-manager:v1:backup-before-v2`，只迁移一次，不重置已录入业务。之后改包装不追溯修改余额和历史流水。

价格优先级：本次送货单价 > 酒吧商品专属售价 > 商品默认售价。专属售价留空恢复默认，允许 0 元赠送。历史送货保存实际单价和包装规格。

删除酒吧前必须结清应收和待回瓶；删除后从客户列表隐藏，历史流水与客户库存保留，不能再为其新增业务。当前未提供恢复入口。

## V1 限制与下一阶段

本地单用户单设备；没有云同步、用户可操作的备份导出、登录或权限。清理缓存、卸载会丢失数据。全量快照和全量列表适合原型规模，长期经营需云存储、分页与归档。暂未实现撤销、退货、期初应收/空瓶录入和财务对账；新增酒吧的应收、空瓶及库存为 0。支持盘点到 0。空瓶按商品区分，尚未建立跨商品共用瓶型、酒筐与押金模型。真机与不同手机尺寸仍需继续测试，未上传发布。

建议下一轮先用真实配送场景验证步骤，再增加误操作撤销/更正、期初余额与空瓶录入、数据备份。流程稳定后，将 services 接口保留并迁移到 CloudBase，补充事务、同步、分页和权限。
